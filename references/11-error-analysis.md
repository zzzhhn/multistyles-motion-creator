# 11 · 错误分析：两部片子里出过的问题、谁发现的、为什么会出、现在怎么防

本文把《八十一难》（2026-10-19 到 21）和《二十四节气》（2026-10-21 到 22）两部片子里出过的问题全部过一遍。每条写：现象、谁发现的、根因、代价、现在在 skill 里的防法。目的是下一部片子开工前先读一遍，把「用户才能发现」的那一类问题提前到自己这里解决。

## 一、按发现者分层（最重要的结论）

| 层 | 谁发现 | 两部片子里的例子 | 结论 |
|---|---|---|---|
| 结构层 | 只有用户 | 单元太短（81 难 v09）；配乐一个旋律重复（v09）、每格重写和声（v10）；画风和主题关联弱（节气 Art Lock v1）；故事感弱、换画风时人物和节气之间没有联系（节气 v1）；四季乐器听不出区别、旋律不好听（节气 v1）；节气名不醒目（节气 v1）；片头推近落点偏（节气 v1） | 逐格审图和代理审片都发现不了。要在开工时用「结构清单」自查（见第四节），并且在大规模铺开之前给用户看能代表结构的小样 |
| 表面层 | 单个粗看代理 | 海报边框在缝上盖住唐僧（81 难）；过渡收尾整屏一跳、题签盖住画风自带的字、片尾字超出月洞门、牛从卧到站一帧跳变（节气 v2） | 一个粗看代理加全片帧差扫描（`scripts/scan.py`）足够；不必派多个审片代理 |
| 契约层 | 工具 | 单元时间不对、记忆点不在拍子上、不确定、帧时超预算、故事轨不连续、谱面音不在调式里或超出乐器音域 | 每类契约都有一条命令检查（`unitsheet` `storycheck` `scorecheck` `audio-check`），交接前必须全过 |

用户在两部片子里提的意见，几乎全部落在结构层。这一层的问题，返工代价最大：节气 v1 到 v2 重做了故事、过渡、标题、片头和整首配乐，花了约一天。

## 二、结构层问题逐条

| # | 现象（用户原话见案例文档） | 根因 | 现在的防法 |
|---|---|---|---|
| S1 | 81 难 v09 每难 2.5 秒，「太短了」 | 按参考片速度定时长，没按「讲清一段情节要几秒」定 | `SKILL.md` 验收口径 3：讲故事的单元 5 到 6 秒；节气用 8 秒（一候一小节） |
| S2 | 81 难 v09、v10 配乐被否 | 配乐跟着画面切分；没有自己的曲式；没先出小样 | `06-music.md`：主线手写 lead sheet，曲式独立于画面；铺满前先出带画面的小样 |
| S3 | 节气 Art Lock v1 的日式、西方画风「本质上和主题的关联性有点弱」 | 照搬了 81 难「全世界画风都可以」的口径，没按新主题重新判断 | `02-bible.md` 选画风规则：先问这个主题的文化归属，默认用这个文化自己的画风；外来画风只在服务内容时用（例如热成像拍「温风至」） |
| S4 | 节气 v1「画面故事感不强」，换画风时主体（农妇、耕牛）没有变化、节气之间没有联系 | 人物只是每个画风各自摆在固定位置的装饰；过渡是随机的生长遮罩；总表只有单元，没有贯穿全片的故事 | `10-story.md`：人物状态是全片时间的函数（引擎算位置、动作、衣服、道具、成长），画风只负责怎么画；过渡由下一单元的自然现象带入；总表加「故事轨」一栏 |
| S5 | 节气 v1「四季乐器听不出来」「旋律没有多好听」「音色不够 authentic & identical」 | 用代码合成民乐（Tone.js），独奏的音色辨识度不够；全片一组五声音阶、同一套旋律块，四季只换乐器；把「卡画面」放在「音乐本身好听」之前 | `06-music.md` 第二课：带文化身份的独奏乐器必须用真实采样；每段有自己的调式和主题（节气按《礼记·月令》配五音，季间旋宫转调）；先查采样和授权（`templates/SAMPLE_RESEARCH_BRIEF.md`） |
| S6 | 节气 v1「有些节气的名字在视频中感觉不太显目」 | 节气名交给每种画风自己写，字体、位置、对比各不相同 | `03-engine.md`：引擎统一画标题卡（自带纸底，任何画风上都清楚），单元只保留自己的小题字；按单元可调位置 |
| S7 | 节气 v1 片头推近「不够丝滑」，落点偏到雨水和惊蛰 | 缩放中心和平移目标是两个点（绕扇区中点缩放，同时平移到扇区里的焦点），推到一半画面漂走 | `03-engine.md`：推近一律以画面中心为缩放中心、目标先居中，按对数插值缩放倍数 |
| S8 | 两部片子都没在铺满前给用户听带画面的配乐小样（81 难的案例文档已写明要先出小样，节气 v1 又没做） | 用户说「做完后就可以把视频也做出来」，我把它当作跳过中间关卡的授权 | `SKILL.md` 流程把「带画面的 45 到 60 秒小样」列为硬关卡；用户明确授权直接做完时，交付时仍附各季（各段）的独立试听片段，并在交付说明里点明「这一项没经过你的耳朵」 |

## 三、表面层和契约层问题

| # | 现象 | 发现者 | 根因 | 防法 |
|---|---|---|---|---|
| T1 | 第 55 难海报边框在缝上盖住唐僧 | 粗看代理 | 单元画了不透明边框，压过了队伍 | `04-unit-standard.md`：行走带让开 |
| T2 | 过渡收尾一帧跳：惊蛰撕裂没盖满全宽；冰片和露珠过渡在最后 8 % 直接整屏填满 | 粗看代理（帧差 15.5，全片最大） | 遮罩宽度算错；用「到某个进度就整屏填满」收尾 | 引擎在每个过渡的最后 20 % 统一交叉淡化并淡出现象层；`scripts/scan.py` 看「过渡末尾」一组的最大帧差 |
| T3 | 题签压住秋分挂图的表头、小暑热像的读数 | 粗看代理 | 引擎标题区和画风自带文字在同一块天空 | 单元简报预留标题区；引擎按单元调标题位置（`JQ.TITLE_POS`） |
| T4 | 片尾「画面由代码逐帧生成……」超出月洞门被裁 | 粗看代理 | 文字没量宽度 | 圆形或窄容器里的文字一律量宽，超了就折行 |
| T5 | 牛从卧到站一帧跳变 | 粗看代理 | 故事轨里卧和站是两个离散姿势 | 卧起用 0.6 秒过渡参数；`storycheck` 检查卧和站跨边界连续 |
| T6 | 人物走过院墙墙面、娃和小牛重叠、农妇站在牛头后面、麦捆跨节气消失、道具名写错（`window`）后什么都不画 | 画风队（他们画人时发现） | 故事数据只在中性底图上看过，没查遮挡和道具连续 | `tools/castsheet.cjs` 每单元 5 个时刻预览；`storycheck` 查连续、滑步、转身、卧站、未知道具；各队交接里写「节气·人物·秒数·问题」，主线统一改数据 |
| T7 | 引擎把负时间传给画风，雨水那格画负半径椭圆报错 | 主线看图 | 过渡时进来的画风拿到 −0.45 秒 | 引擎把画风时间夹在 0 到 9；契约写进 `film.js` 文件头 |
| T8 | 竖版和方版第一次导出没有音轨 | 主线测响度时发现 | 平台页是手抄的脚本列表，漏了一个乐器脚本 | 平台页一律由主片页生成（81 难用的 `mkplatform.cjs`），不手抄；导出检查里「有音轨」必须过 |
| T9 | 谱面音超出乐器音域（二胡降八度低于 D4、笛子到 G6、大提琴低于 C2、古筝采样只到 C#6）；高潮力度让母带限幅一直工作 | 渲染代理 | `scorecheck` 只查了旋律，不查各层和采样覆盖 | `scorecheck` 查独奏和对位声部的音域、力度上限 6（超过要显式标 `allowLoud`）；渲染简报要求报告每个声部的音域处理和母带限幅量 |
| T10 | 试导出 20 秒却导了整片 216 秒（多花约 100 秒和 800 MB） | 主线 | 运行时不认 `from` / `to` 参数 | 运行时支持区间导出（片段画面和配乐一起裁） |

## 四、协作和工具问题

| # | 现象 | 防法 |
|---|---|---|
| C1 | 同一个子代理连续两次 API 返回空响应而中断 | 第一次用 SendMessage 续跑；第二次换一个新代理，接着旧代理留下的文件做，简报里写明「先评估已有文件，能修就修」 |
| C2 | 子代理一次读很多图，请求过大 | 简报里写「每次 Read 只读一张图」 |
| C3 | 多队同时写各自的画风文件，页面加载到别队写了一半的文件报语法错误 | 页面对每个单元容错（坏了的格退回占位）；简报里告诉各队「报错指向别人的文件就忽略，稍后重跑」；导出前对全部源文件跑一次 `node --check` |
| C4 | 子代理写报告文件被运行环境拦下（只允许返回文字） | 让子代理在交接里返回全文，主线落盘 |
| C5 | 主线的 Bash 权限检查超时两次 | 等十几秒重试；改文件可以先用编辑工具；不要换绕路的办法 |
| C6 | shell 工作目录停在子目录，下一条用相对路径的命令全部失败 | 每条命令开头 `cd` 到工程根目录的绝对路径 |
| C7 | 系统 Python 没有 numpy | 分析脚本用音频工具的虚拟环境（`$AUDIO_TOOLS/.venv/bin/python`） |
| C8 | 个别子代理用 sed 或 python 原地改文件、单次写超过 150 行 | 简报里写明，交接里如实报告；不影响结果的偏差不返工 |
| C9 | 公开仓库第一次准备时，文档和工具里有本机绝对路径、本机 agent 名、写死的 Playwright 路径、缺的第三方许可证 | 发布前跑一遍脱敏清单（见 `07-review-delivery.md`），工具路径一律用环境变量或相对路径 |

## 五、做对了、要保留的

- **Art Lock 先看图再拍板**（`09-art-lock.md`）：两轮就把画风定下来，省掉了整片铺开后再换画风的代价。
- **四支季节队、每轮带上下文续跑**：同一批代理连续做了四轮（Art Lock、换中国画风、扩成 8 秒、接故事轨），每轮 1 到 2 小时。
- **故事轨和画风分离**：一次改故事数据，24 种画风同时跟着变；连续性用一条命令就能验证。
- **一条命令、确定性的配乐构建**：谱面改完 36 秒出新版，哈希一致，24 个重音对齐误差不超过 1.4 毫秒。
- **只派一个粗看代理加帧差扫描**：v2 找出 5 处真问题，修完再扫一遍确认。

## 六、开工前的结构清单（把用户层的问题提前）

1. 单元时长够讲清一段吗（讲故事 5 到 8 秒）？
2. 画风和主题的文化关联，用户要多紧？默认是主题本身的文化。
3. 贯穿全片的主体是谁？它在每个单元做什么、身上有什么变化（衣服、成长、道具）？换画风时它在不在原地？
4. 单元之间怎么连？过渡有没有内容上的理由（下一单元的现象、上一单元的动作）？
5. 每个单元的名字（标题）在任何画风上都看得清吗？谁负责画？
6. 片头片尾有没有一个能被记住的画面（节气用日晷加月洞门），推近有没有漂？
7. 配乐有没有自己的曲式？每一段能不能单凭耳朵分辨（调式、主题、独奏音色）？独奏是不是真实乐器？
8. 铺满之前，给用户看过带画面的小样吗？
